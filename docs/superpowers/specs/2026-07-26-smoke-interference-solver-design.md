# 烟幕干扰弹投放策略 Python 求解系统设计

## 1. 文档目的

本文规定 2025 国赛 A 题问题 1 至问题 5 的 Python 代码架构、模块边界、数据流、配置档位、异常处理、测试方法和输出规范，作为后续实施计划与代码开发的唯一工程设计依据。

设计目标是在不改变现有模型口径的前提下，交付可独立运行、可追溯、可测试的五问求解程序。程序默认使用快速可复现配置，同时提供竞赛级高精度配置；快速配置所得优化解必须明确标记为快速搜索结果，不得表述为竞赛级全局最优解。

## 3. 核心内容

### 3.1 总体架构

采用“问题 1 提供稳定公共评价接口，问题 2 至问题 5 逐级复用”的架构。每个小问仍保留规定的五文件结构：

```text
2025国赛/A/
├── configs/
│   ├── quick.json
│   └── competition.json
├── question1/
│   ├── main.py
│   ├── data_processing.py
│   ├── model.py
│   ├── evaluation.py
│   └── visualization.py
├── question2/ ... question5/
└── tests/
```

不新增必须提交的公共源码包。Q2—Q5 通过稳定导入接口复用 Q1 的题面数据、运动学、几何判定、联合覆盖和连续区间评价，避免五份几何公式独立演化。各问题目录中的同名文件负责该小问特有的数据准备、优化、评价、绘图和入口调度。

### 3.2 公共数据与符号映射

程序内部统一使用 SI 单位和弧度制。核心数据对象包括：

- `ProblemData`：题面坐标、速度、目标尺寸、烟幕参数、重力和编号映射；
- `SamplingConfig`：圆柱侧面、顶面与轮廓采样参数；
- `NumericalConfig`：时间步长、求根容差、区间合并容差和收敛阈值；
- `OptimizationConfig`：主种子、PSO/DE 预算、停止条件和候选规模；
- `BombPlan`、`UAVPlan`：独立决策变量及其派生投放点、起爆点；
- `EvaluationResult`：可行性、区间、时长、边界残差、贡献和诊断信息。

独立决策量严格采用文档中的 $\theta_i,v_i,t^r_{ik},\tau_{ik}$。投放点和起爆点由轨迹正向计算，不作为独立自由变量。

### 3.3 公共评价内核

Q1 的公共内核依次实现：

1. 导弹匀速直线运动、无人机等高度直线运动、烟幕弹抛体运动和云团下沉；
2. 圆柱目标表面采样及从导弹视角的可见点过滤；
3. 云团中心到导弹—目标点有限线段的最短距离，投影参数限制在 `[0,1]`；
4. `blocked[B,N] -> point_covered[N] -> joint_blocked` 的多云团逐点共同遮蔽判据；
5. 活动时间窗、地面失效、导弹终止和烟幕寿命事件处理；
6. 时间扫描、边界细化、区间合并与连续遮蔽时长计算；
7. 空云团、空采样点、零长度区间、相切边界和浮点容差处理。

快速评价器使用较疏目标采样和时间网格，用于优化候选筛选；验证评价器加密时间和空间配置，并记录两级评价差异。两者共享完全相同的物理和遮蔽判据。

### 3.4 五个小问的实现边界

#### 问题 1

代入固定 FY1 策略，输出投放点、起爆点、有效窗、遮蔽区间、总时长和收敛记录。问题 1 不使用随机数，是公共评价器的首个端到端验收入口。

#### 问题 2

决策变量为 4 维单弹参数。自定义 PSO 与 SciPy DE 使用相同变量边界、快速评价器和近似函数评价预算独立搜索；候选统一用验证评价器回代，最终按验证目标选择。

#### 问题 3

决策变量为共享航向速度和三枚弹时序。有序解码保证相邻投放至少间隔 1 秒，但不强制起爆顺序。输出独立时长、顺序新增时长、移除边际贡献和复制填写后的 `result1.xlsx`。

#### 问题 4

FY1—FY3 各使用一组 4 维变量。先生成多样化单机候选，再进行组合筛选和联合 PSO/DE 搜索。输出三机联合区间、顺序新增时长、移除边际贡献和 `result2.xlsx`。

#### 问题 5

为每架无人机建立含空路线在内的 0—3 弹完整路线库，覆盖数据使用布尔位集或压缩数组。整数编码 PSO 第一阶段最大化 $J_{\mathrm{sum}}$，第二阶段在总和容差内最大化 $J_{\min}$，随后使用 DE 对已选路线进行连续精修。所有云团对 M1—M3 的实际几何遮蔽均计分，任务标签仅用于解释与 Excel 输出。最终复制填写 `result3.xlsx`。

### 3.5 配置设计

`configs/quick.json` 是默认配置，用于自动测试、接口验证和全流程快速复现。它采用较疏采样、较小种群和较低迭代预算，并在输出清单中标记 `profile=quick`。

`configs/competition.json` 采用加密采样、更严格容差、更多随机种子、更大候选库和更高 PSO/DE 预算，并标记 `profile=competition`。竞赛配置的实际数值将在实施阶段基于 Q1 收敛试验和运行资源确定，不在设计阶段虚构运行效果。

两个配置均固定 `MASTER_SEED=2025`。所有随机任务由顶层 `SeedSequence` 派生子种子，禁止使用未显式传入的全局随机状态。

### 3.6 命令行与数据流

统一运行方式为：

```powershell
E:\Anaconda\envs\newShuMo\python.exe question1\main.py --config configs\quick.json
E:\Anaconda\envs\newShuMo\python.exe question5\main.py --config configs\competition.json
```

每个入口执行以下数据流：读取配置与题面常量 → 校验输入和模板 → 构造/读取候选 → 求解 → 验证评价 → 保存完整精度结果 → 生成英文图表 → 必要时复制填写 Excel → 回读校验。

Q2—Q5 不强制依赖前一问已经运行产生的文件；若前序候选存在且配置哈希一致，可以复用缓存，否则重新生成，从而保证每个小问可独立执行。

### 3.7 异常处理与状态报告

程序对以下情况抛出明确异常或生成失败状态：

- 输入坐标含非有限值、数组维度错误或导弹初始位置范数为零；
- 配置缺字段、物理常数非法、正式重力不等于 9.8；
- 速度、投放时刻、起爆高度、投放间隔或资源数量不满足约束；
- 目标可见采样点为空；
- 优化器未产生任何可行候选或达到预算但未收敛；
- Excel 工作表、表头、记录数量或编号与模板不一致；
- Excel 舍入回读后无法重建可行轨迹，或时长差超过配置容差。

优化未收敛不等同于程序崩溃。程序应保存当前最好可行候选和终止原因，但不得将其描述为已证明最优。

### 3.8 输出与可追溯性

每次运行创建独立目录，至少包含：

```text
outputs/questionN/<run_id>/
├── manifest.json
├── config.json
├── input_snapshot.json
├── raw_solution.json
├── intervals.csv
├── optimization_history.csv
├── convergence.csv
├── logs/
├── figures/
└── excel/
```

`manifest.json` 保存配置档位、随机种子、解释器与依赖版本、输入文件哈希、Git 状态、开始/结束时间和终止原因。图表标题、坐标轴和图例全部使用英文，同时保存 PNG 和 SVG。结构化数值文件保留完整精度，Excel 仅按三位小数生成提交副本。

### 3.9 测试与验证

开发遵循测试驱动流程，先写失败测试，再实现最小功能。测试至少覆盖：

- 导弹终点、无人机等高度、弹道与起爆点公式；
- 有限线段投影、端点截断、相切闭边界；
- 两云团分别覆盖两个目标点时联合遮蔽为真、单云团完整遮蔽均为假；
- 空区间、重叠区间、不连续区间和零长度区间；
- 速度边界、起爆高度、投放间隔、Q3 弹数和 Q5 每机弹数；
- 固定种子下 PSO/DE 的可复现性和小型人工最优问题；
- Excel 表头拒绝、模板不覆盖、三位小数与回读重建；
- 五个 `main.py` 在快速配置下的端到端冒烟运行。

完成前执行全量 pytest、五问快速配置运行、结构化输出检查和文档要求逐项核对。竞赛配置至少完成配置解析、约束检查和受控小预算启动验证；只有实际完成竞赛配置全量运行后，才能报告相应高精度结果。

## 4. 关键结论

1. 采用 Q1 公共评价内核、Q2—Q5 稳定接口复用的方案，在保持五文件目录结构的同时避免模型口径漂移。
2. 默认交付快速可复现配置，并提供竞赛级配置；两种结果在运行清单和文档中明确区分。
3. 多云团联合遮蔽、地面失效、问题 5 字典序目标、实际几何遮蔽计分和 Excel 输出规则全部沿用现有模型文档。
4. 完整精度结构化结果是科学结论来源，Excel 是三位小数提交副本，必须回读验证。
5. 代码实现以测试驱动和实际运行证据为验收依据，不预填或虚构任何遮蔽时长、最优策略、收敛次数和运行时间。
